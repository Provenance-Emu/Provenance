# Controller-mapping audit

Generated by `Scripts/audit_controls.py`. For each system the matrix shows what GameController button (or stick axis) drives each emulator input, per controller class and platform. **MISSING** = the button exists in the system's enum but has no `case` in that controller-class block, so a player on that hardware cannot reach it.


## Cross-core discrepancies (same system, different cores)

Buttons that have **different mappings** for the same system across cores.

**Layer note:** these two columns measure different things and aren't perfectly comparable, but divergence is still useful signal:
- _native_ column = which physical GameController button is read each frame by the core (e.g. `rightTrigger`).
- _PVRetroArchCore_ column = which **virtual** GC event the on-screen touch control fires (RetroArch then maps that virtual event to a libretro button via its own configuration).

Discrepancies on `Start`/`Select`/`Mode`/shoulder buttons are usually real UX bugs (different physical button presses Start across cores). Discrepancies on face A/B/X/Y are often layer artifacts and need manual review.
