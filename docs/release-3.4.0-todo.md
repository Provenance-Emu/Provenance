  - Serial-first performance, scoped ([#2787](https://github.com/Provenance-Emu/Provenance/issues/2787)):

    - What is left is the cost of the identity hash. A set hashes one track. A single-file image hashes the whole file, which is gigabytes for a DVD image or a CHD.
    - First step: measure on a device. The importer already logs the serial time and the MD5 time for each disc. No work is justified without those numbers.
    - If the numbers are bad, the cheap fix for CHDs is an identity taken from the SHA-1 in the CHD header (20 bytes, no hashing). That changes the identity of every CHD already imported, so it needs the same legacy match cue sets got, and the other apps that share libraries by MD5 would have to agree. Owner decision.
    - Loose ends in the serial path: no PVLibrary test covers it; the match type is not recorded; and when a disc has no `SYSTEM.CNF` the ISO and CHD readers return the volume name as the serial, which is then stored on the game and looked up.
