### Fixed
- **Hatari TOS word-swap** — detect and correct fully byte-swapped TOS ROM images (first bytes `0x1A 0x60`); the Hatari libretro v1.8.0 core does not auto-swap these, causing "not a valid TOS ROM file" and a subsequent crash in the SDL preferences dialog.
- **Hatari crash on invalid TOS** — set `nAlertDlgLogLevel = 0` in bundled `hatari.cfg` to suppress non-fatal SDL GUI alert dialogs that crash in the libretro context when no real SDL display is present.
- **Hatari partially-repaired TOS** — fix edge case where a TOS file that had only its address bytes corrected by older code would pass address validation but still have the word-swapped BRA instruction at bytes 0–1; now checks both address and BRA bytes before accepting a candidate as valid.
- **Hatari TOS post-swap address fix** — after a full word-swap repair, re-validate the load address and correct it if the file was previously partially fixed (preventing the swap from re-breaking address bytes 8–11).
- **Hatari hatari.cfg TOS path substitution** — add regex fallback in `writeHatariConfigForSystemDir:` for templates where spacing around `=` differs; also verify the substitution succeeded and log a warning if not.

### Added
- **Hatari TOS .rom file support** — BIOS search now recognises `.rom`-extension TOS images (e.g. `tos100us.rom`, `tos104us.rom`, `tos206uk.rom`); these are common in TOSEC and other ROM packs.
- **Hatari TOS BIOS import** — added BIOS database entries for `tos100us.rom`, `tos102us.rom`, `tos104us.rom`, `tos104se.rom`, `tos106us.rom`, `tos205us.rom`, `tos206uk.rom`, and `tos206us.rom` so the importer recognises these filenames without requiring a manual rename.
- **Hatari TOS diagnostic logging** — log TOS version bytes, load address, and BRA instruction at every validation step; the pre-boot inventory now shows version numbers (`1.02`, `2.06`, etc.) alongside raw hex to make mismatches immediately obvious.
