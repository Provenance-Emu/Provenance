# SNES Mouse Fix

## Bug Fixes

- **fix(snes/native)**: Fix P2 button report operator precedence (`(player+1 << 16)` → `((player+1) << 16)`) in native snes9x core, correcting P2 controller input for all SNES games
- **fix(retroarch/snes)**: `PVRetroArchCoreCore` now implements `PortDeviceConfigurable` and automatically sets SNES port 2 to `RETRO_DEVICE_MOUSE` for known SNES Mouse games (Mario Paint, Mario & Wario, etc.) after the game loads
- **fix(retroarch/mouse)**: Add `setControllerPortDevice:forPort:` to `PVRetroArchCoreBridge` to expose `core_set_controller_port_device()` for per-port device type configuration
- **fix(retroarch/mouse)**: Fix `dos_uses_relative_mouse()` to always try the static system/core identifier fallback, enabling relative-delta mouse input for SNES (and Saturn/PSX) RetroArch cores even when those cores declare controller port info without explicitly listing `RETRO_DEVICE_MOUSE`

## Summary

SNES Mouse support (Mario Paint, Mario & Wario, Undead Line, etc.) was broken across all core types:

- **Native snes9x**: P2 button inputs were broken by an operator precedence bug. Mouse movement worked but button reports went to the wrong bitmask for player 2.
- **RetroArch SNES**: The libretro port was never switched from joypad to mouse device type, so the SNES core never received mouse input queries. Additionally, the relative-mouse routing in the input bridge exited too early when controller port info was declared, preventing touch-mouse events from reaching the correct `mouse_rel_x/y` fields.
