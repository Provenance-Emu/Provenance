### Fixed
- **Hatari/Atari ST crash** — `hatari_boot_hd` option was set to `"false"` (an invalid value); changed to `"disabled"` which is the value the hatari libretro core actually accepts. The old in-place repair was incorrectly replacing valid `"disabled"` values with invalid `"false"`, making things worse; it now corrects any wrong variant (`"false"`, `"true"`, `"enabled"`) back to `"disabled"`.
- **Hatari TOS byte-swap repair** — byte-swapped TOS ROM load addresses (`$fc00` instead of `$fc0000`) were only repaired during `writeConfigFile`. When `syncResources` ran afterwards and copied a byte-swapped `tos.img` from the BIOS directory, the repair code had already finished and the bad file went unfixed, causing Hatari to open its SDL config dialog (which crashes with a null function pointer in libretro context). A second repair pass now runs after `syncResources` to catch this case.
